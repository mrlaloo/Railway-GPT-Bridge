# AI Board Grok Relay

This service connects the GitHub engineering board to xAI/Grok without changing the existing read-only Railway MCP bridge.

## What it does

- Watches new issue comments in `BOARD_REPO`.
- Ignores comments already generated by Grok and comments containing `<!-- ai-board:no-relay -->`.
- Builds context from the issue body plus recent thread comments.
- Redacts common secret/token patterns before sending context to xAI.
- Calls the xAI Responses API using `grok-4.6` by default.
- Posts Grok's answer back to the same GitHub issue.
- Adds a hidden `source-comment-id` marker so restarts/retries do not duplicate replies.
- Logs xAI request cost when the API returns cost metadata.
- Has no broker or deployment credentials and no trading/deployment action path.

## Required Railway variables

- `GITHUB_TOKEN` — token able to read issues and create issue comments in the board repository.
- `XAI_API_KEY` — xAI API key.

## Recommended Railway variables

- `BOARD_REPO=mrlaloo/Railway-GPT-Bridge`
- `XAI_MODEL=grok-4.6`
- `POLL_SECONDS=30`
- `BOOT_LOOKBACK_MINUTES=1440`
- `MAX_CONTEXT_COMMENTS=16`
- `MAX_INPUT_CHARS=50000`
- `MAX_OUTPUT_TOKENS=1800`
- `OVERLAP_SECONDS=120`
- `RELAY_ADMIN_SECRET=<random secret>` — optional, enables authenticated `POST /run-once`.

## Railway service

Deploy this repository as a second Railway service with:

- Root directory: `/relay`
- Start command: `npm start`
- Healthcheck: `/health`

Do not point the existing `Railway-GPT-Bridge` service at `/relay`; keep the MCP bridge and discussion relay as separate services.

## Board behavior

Any normal issue comment is eligible for Grok review. A generated Grok reply contains a marker like:

`<!-- ai-board:provider=grok source-comment-id=123 model=grok-4.6 ... -->`

That marker is also the durable idempotency record. If the service restarts and sees comment `123` again, it finds the existing Grok reply and skips it.

To suppress relay processing for a comment, include:

`<!-- ai-board:no-relay -->`

## Security boundaries

- Never store xAI, GitHub, broker, or Railway credentials in issue text.
- The relay attempts to redact common key/token formats before sending board content to xAI, but this is defense-in-depth, not a substitute for keeping secrets out of the board.
- The relay cannot deploy code, place trades, change broker configuration, or access broker accounts.
